# プレビューを「マインクラフトのブロックの色」で見る切りかえ

日付: 2026-11-15 / ブランチ: `work/mc-preview` (`main` の 0878853 から)

## 目的
ユーザーがイラスト (青と赤のロボと箱) をマインクラフトに置いたら、色が崩れた (青があざやかな水色、赤がピンクと橙のまだら、ふちが灰色や紫)。ユーザーの考え: 「プレビューで見ているものと出力されたものが違うのが良くない」。プレビューで置かれるブロックの色を見られる切りかえを足すことになった (ユーザーが「切りかえを足す」を選んだ。いつもブロックの色で描く案は選ばなかった)。

## 調べてわかったこと (直す前)
- 色の選び方 (`mcNearest()`、OKLab) はまちがっていない。49 種類のブロックに、明るくくすんだ色 (珊瑚色、くすんだ水色、うすい橙) に近いものがない。たとえば `#d48078` は、いちばん近い `pink_concrete` でも OKLab の距離 0.08 (同じ色に見えるのは 0.02 くらい)。`pink_*` と `orange_*` がほぼ同じ距離なので、まだらになる。
- プレビュー (`buildMesh()`) は `g.col` (元の色) で描き、保存 (`mcBlocks()`) だけが `mcNearest()` で置きかえていた。そのため、置くまで崩れに気づけなかった。
- 同じ会話で、「写真をイラストにする」をオンにすると汚くなる件も調べた (コードは変えていない)。原因は輪郭線 (`lineMode`): 色の境目すべてに `LINE_RGB` の線を引き、作業用の画像 (`WORK = 320`) を 64 マスにするとセルが約 5 px になり、線のある画素が 25% 以上のセルが線のブロックになる。もとのイラストに線があると、線が 2 マスの太さになる。青いロボが消えたのは「いちばん大きいかたまりだけ残す」のため。

## やったこと
- `index.html`
  - 書き出しの欄に、チェックボックス `#mcView`「マインクラフトのブロックの色で見る」(行は `#mcViewRow`) と、説明 `#mcViewNote` を足した。
  - `MC_RGB` (ブロック名 → 平均の色の `Map`、`MC_PALETTE` から作る) を足した。
  - `buildMesh()`: `#mcView` がオンで、風景でないときは、各ブロックを `MC_RGB.get(mcNearest(...))` の色で描く。保存と同じ関数なので、見える色と置かれるブロックが一致する。オンのときは、下の数の表示に「・ マインクラフトの色」を足す。
  - `setMode()`: 風景のタブでは `#mcViewRow` と `#mcViewNote` を隠す (風景はもともと材料ごとの色で描いていて、書き出しも材料から決めるため)。
  - `#mcView` の `input` で `schedule()` (立体を描き直す)。
- `docs/public/minecraft.md` / `docs/public/minecraft.html`: 「何のブロックになるか」の 49 種類の段落に、保存する前にこの切りかえで確かめられることを 1 文足した。`python3 tools/build_guide.py` で `minecraft.html` を作り直した。

## 追記: 色を選ぶブロックを 49 → 72 種類に増やした (同じ日)
ユーザーが「ブロックを足した場合の結果をみてみたい」と言い、試した結果を見て「板を外して試す」、そのあと「OK」と言った。

- `index.html` の `MC_PALETTE` に 23 種類を足した: `andesite` `blue_ice` `calcite` `clay` `end_stone` `lapis_block` `moss_block` `mud` `nether_wart_block` `packed_ice` `packed_mud` `polished_blackstone` `polished_tuff` `quartz_block` `smooth_basalt` `smooth_red_sandstone` `smooth_sandstone` `snow_block` `stone` `warped_wart_block` `waxed_copper_block` `waxed_exposed_copper` `waxed_weathered_copper`。
  - 色は Mojang が公開している統合版の絵 (`Mojang/bedrock-samples` v1.26.60.5、`resource_pack/textures/blocks/`) の平均。元の 49 種類は、この絵の平均と全色一致することを確かめてある (`zenn-drafts/tools/check_bedrock_palette.py`、リポジトリの外)。足した 23 種類が Java 版の絵と同じかは **未確認**。
  - 選び方: 絵の明るさのばらつき (OKLab の L の標準偏差) が 0.065 以下で、1.21 にあるブロック。外したもの: コンクリートパウダー (落ちる)、ふつうの銅 (さびて色が変わる。ろう引きを使う)、`pale_moss_block` (1.21.4 から。1.21.0〜1.21.3 では関数の読み込みエラーになる)、木の板 6 種類。
  - **木の板を外した理由**: 板ありの 78 種類で試すと、文字の初期設定のグラデーション (橙 → 黄緑) の 15 段のうち 9 段が `birch_planks` になり、くすんだ。板なしなら 15 段は前と同じ (橙 4 → 黄色のテラコッタ 6 → 黄緑 5)。
- 結果 (ユーザーのイラスト「青と赤のロボと箱」の下絵で、ブラウザで「マインクラフトのブロックの色で見る」をオンにしてくらべた): 青いロボはあざやかな `light_blue_wool` から `blue_ice` / `packed_ice` に、箱は灰色と黄色の点から `smooth_sandstone` 中心に変わった。赤いロボは `waxed_copper_block` が入るが、ピンクと橙のまだらは残る (明るい赤に合うブロックがない)。
- `docs/public/minecraft.md` / `minecraft.html`: 「49 種類のブロック (コンクリート・羊毛・テラコッタ)」を「72 種類のブロック (コンクリート・羊毛・テラコッタと、石・氷・粘土・砂岩・ろう引きの銅など)」に直し、`python3 tools/build_guide.py`。
- 照合: 今の本体で 5 種類のデータパックを書き出し (`gen_packs.js` の写し。GA のタグの `<script>` を飛ばす)、`offline_check.py` で、置く・壊すのちがい 0、残り 0、書式エラー 0。ただし文字と画像は前に保存した zip からブロック名を読み戻して使う道具なので、**新しい色の選び方で選ばれたブロック名の照合にはなっていない**。
- 足したブロックで、置いたあとにひとりでに変わるものはない (雪ブロック・氷塊・青氷は溶けない、ろう引きの銅はさびない)。これは Claude の知識で、ゲームやサーバーでは確かめていない。
- Zenn の記事 (リポジトリの外の下書き) は「49 種類」のまま。この変更を公開したら直すか決める。
