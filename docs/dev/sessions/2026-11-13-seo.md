# 検索と共有のための設定を足す

日付: 2026-11-13

## 目的
ユーザーが「サイトと Zenn の SEO を調整していきたい」と言った。調べた結果を伝え、「サイトから直して」と言われた。

## 調べてわかったこと (変更前)
- `index.html`: `<title>` が「ボクセル工房」だけ。説明文 (`meta name="description"`)、共有用の指定 (`og:*`, `twitter:card`)、
  正式な URL (`rel="canonical"`)、言語の指定がなかった。`<!doctype>` も `<html>` もない。
- `guide.html`: `<html lang="ja">` はあるが、ほかは同じくなかった。
- 公開先に `robots.txt` と `sitemap.xml` はない (どちらも 404)。

## やったこと
- `index.html`: 先頭に `<html lang="ja">` を足した。`<title>` を「ボクセル工房 — 文字・画像・風景をブロックの立体に」に変えた。
  説明文、`rel="canonical"`、`og:*` (10 個)、`twitter:card` (`summary_large_image`) を足した。
- `tools/build_guide.py`: `HEAD` に、説明ページ用の同じ種類のタグを足した (`guide.html` は生成物なので、ここを直す)。
  `guide.html` の `<title>` は本文 (`docs/public/index.html`) にあるので「ボクセル工房のてびき」のまま。`og:title` だけ長い題にした。
- `docs/public/images/og.jpg`: 共有用の画像 (1200×630、約 70KB)。風景 (山と湖・夏・番号 12・64 マス) の画面に、
  「ボクセル工房」と「文字・画像・風景を、ブロックの立体に」の文字を HTML で重ねたもの。AI が描いた絵ではなく、本体の画面そのもの。
  置き場所を `docs/public/images/` にしたのは、公開の自動処理がこのフォルダをそのまま公開先に置くため (自動処理は変えていない)。
- `docs/public/index.md`, `docs/public/index.html`: 風景の説明のあとに、Zenn の記事 (風景の番号のしくみ) へのリンクを足した。
- 作業ブランチ `work/seo`。

## 共有用の画像の作り方 (作り直すとき)
1. `index.html` の写しを作り、最後の `})();` の前に、撮影用の処理を足す (横の操作欄と上のボタンを隠す、`setMode('scene')`、
   文字を重ねる、`camera.setViewOffset()` で立体を右に寄せる)。写しはリポジトリに入れていない。
2. ヘッドレス Chrome で撮る: `--headless=new --enable-unsafe-swiftshader --force-device-scale-factor=1 --window-size=1200,630 --virtual-time-budget=9000 --screenshot=...`
3. PNG を JPEG (品質 88) にして `docs/public/images/og.jpg` に置き、画像を開いて確かめる。

## 決めたこと
- `index.html` に `<!doctype html>` は足さなかった (Claude の判断)。足すと描画の決まりが変わり (今は `document.compatMode` が `BackCompat`)、
  配置がずれるおそれがある。検索への効果は小さいので、見た目を変えないほうを選んだ。
- `robots.txt` と `sitemap.xml` は足さなかった。公開の自動処理 (`.github/workflows/deploy.yml`) が置くファイルを決めていて、
  足すには自動処理を変える必要がある (自動化の変更はユーザーに確認してから)。ページは 2 つだけなので効果も小さい。
- Google Search Console の登録はユーザー自身の操作。確認用のタグは、ユーザーから値をもらってから入れる。
