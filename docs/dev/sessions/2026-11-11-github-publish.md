## 会話の中で決まったこと
- 公開するのは voxel-maker だけ。Gemini との協調の道具 (別フォルダ) は出さない。
- 挿絵の絵柄はフラットイラストで確定 (2026-11-10)。
- ライセンスは MIT、著作権の表示の名前は GitHub のアカウント名にする (ユーザーが選んだ)。`LICENSE` を追加し、`README.md` に節を足した。

## 追記: 公開元を gh-pages にする
- ユーザーは、ほかのリポジトリに合わせて `gh-pages` ブランチを公開元にしたいと言った。
- 最初に GitHub Actions (`.github/workflows/deploy.yml`) で `main` への push のたびに `gh-pages` を作る形にして送った。1 回動いて `gh-pages` ができた。
- そのあとユーザーが「自動で別ブランチを作るのは望まない」と言ったので、ワークフローを削除し、手で実行する `tools/publish_pages.sh` に置き換えた。
- `gh-pages` ブランチ自体は、ワークフローが作ったものが GitHub に残っている (中身は公開用のファイルだけ)。

## 追記: ブランチの構成を決めた
- ユーザーの指摘: `main` の変更で `gh-pages` を自動で更新するなら、作業用のブランチがあることが前提になる。
- 4 つの形 (常設の `dev` / 作業ごとの短いブランチ / タグで公開 / 手動) を比べ、ユーザーが「作業ごとの短いブランチ」を選んだ。
- これに合わせて `.github/workflows/deploy.yml` を戻し、手動用の `tools/publish_pages.sh` は消した。この変更自体を、最初の作業ブランチ `work/pages-auto-publish` で行った。

## 追記: 公開された
- ユーザーが Settings → Pages で公開元を `gh-pages` ブランチのルートにした。
- 確認済み: https://fu-yu.github.io/voxel-maker/ で本体が動く (文字の立体が出る、コンソールエラーなし)。`guide.html` は 375px 幅で横スクロールなし、画像 2 枚と書体が読み込まれる。
- 作業ブランチ `work/public-url` で、公開先の URL を `README.md`・説明ページ・`PUBLISHED.md` に書いた。
- 失敗の記録: 作業ブランチの取り込みで `git merge -F -` を使ったら失敗し (merge は標準入力からメッセージを読めない)、続けて書いていたブランチ削除が先に走った。コミットは残っていたのでハッシュから取り込み直した。取り込みと削除は別々のコマンドにし、メッセージは `-m` で渡す。

## 追記: 本体の色合いを説明ページに合わせた
- ユーザーの依頼: 「サイトの色合いも説明ページのテイストに合わせたい」。作業ブランチ `work/warm-colors`。
- `index.html`: `:root` の色の変数 (明るい画面・暗い画面) を、説明ページと同じ生成り・こげ茶・オレンジに置き換えた。立体の背景 (`--stage`) と `applyTheme()` の予備の色も同じ系統にした。説明へのリンクの色を `--accent` にした。
- 変えていないもの: 書体、配置、文字の立体の初期の色 (オレンジ→青)、three.js の光の色。
- 確認済み: ローカルの静的サーバーで、明るい画面・暗い画面 (幅 1200px) のスクリーンショット、コンソールエラーなし。文字のコントラストは計算で 4.5 以上 (薄い文字 5.0、ボタンの文字 5.3)。
- 色の確認の途中で見つけた不具合: `index.html` に `<meta name="viewport">` がなく、スマホ幅でも 980px 幅のデスクトップ用の配置で表示されていた (公開中のページでも同じ。Artifact として作られたファイルで、Artifact では外側の枠がこの指定を足していたため)。同じ作業ブランチで 1 行足して直した。
- 確認済み (ローカル、375px 幅): `innerWidth` 375、横スクロールなし、立体が上・操作が下の配置になる。画像タブの下絵の格子模様も新しい色で見える。
- **未解決**: 375px 幅では、文字の立体 (横 64 マス) が画面の左右にはみ出して表示される。カメラの引きが縦長の画面に合っていない。今回は直していない。
- **未確認**: 実機の Android。

## 追記: 縦長の画面で立体がはみ出すのを直した
- 作業ブランチ `work/fit-narrow`。`index.html` の `fitCamera()`: これまで縦の視野角だけで距離を決めていた。画面の縦横比から横の視野角を出し、狭いほうに合わせるようにした。横長の画面では結果は変わらない。
- 確認済み (ローカル): 375px 幅で「ボクセル」(64×15×9) と見本のきのこ (16×16×9) の全体が入る。1200px 幅は以前と同じ見え方。コンソールエラーなし。
- 画面の向きを変えたとき (幅だけが変わったとき) に引き直す処理は入れていない。「視点を戻す」を押せば合う。

## 追記: 文字のデモの初期の色
- ユーザーの依頼: 「ボクセルの文字のデモも色合いを揃えたい」。まだ取り込んでいなかった `work/fit-narrow` に、別のコミットとして足した。
- `index.html`: 色の入力の初期値を `#ff7a45`→`#f08a3c` (オレンジ)、`#3d6bff`→`#7fa9dc` (青) に変えた。説明ページの `--orange` と `--blue` と同じ値。
- 確認済み (ローカル、幅 1200px、明るい画面と暗い画面)。グラデーションの中ほどは、オレンジと青が混ざって灰色がかって見える。
- そのあとユーザーが「青系ではなく、サイトの色から選んだ別の色合いがよい」と言った。3 案を画面で見比べた: (A) オレンジ→ボタンの濃いオレンジ茶 `#ad4c0b`、(B) オレンジ→若草色 `#8fbf5a`、(C) 明るい黄オレンジ→濃いオレンジ。A を採用 (2 色ともサイトにある色で、中ほどが濁らない。Claude の判断)。おわりの色の初期値を `#ad4c0b` にした。
- 確認済み (ローカル、幅 1000px、明るい画面と暗い画面): A は両方で形が読める。色の差は青のときより小さい。

## 試してうまくいかなかったこと
- 頼まれていない自動化 (GitHub Actions) を入れて、取り消すことになった。公開のやり方は先に確認する。

- アプリ内のブラウザは GitHub にサインインしていない。リポジトリの作成と Pages の設定はユーザーの操作が要る。
