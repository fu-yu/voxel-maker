# 山の上から水を流す (マインクラフト用の書き出し)

日付: 2026-11-20

## 目的
ユーザーが、高い所から低い所へ水が流れるシミュレーションをやってみたいと言った。案 A (マインクラフトに水の源を置き、流れはゲームに計算させる) と案 B (ボクセル工房の中で流れを計算する) のうち、「まずAで」と決まった。
書き出しを変えずに試した結果を見せたところ、ユーザーは「外にこぼれない峰だけ」に水を置く設定を足すと決めた。

## 書き出しを変えずに試した結果 (main のまま)
- 風景: 山と湖・夏・番号12・48マス・山の高さ16・水25%・木40%・小さな緑の木。公式サーバー26.3 (平らな世界) で `execute positioned 0 -60 0 run function voxel:build`。
- 峰5か所に `setblock` で水源を置き、5秒・30秒・2分・5分で保存して調べた。流れは5秒 (100ティック) で止まり、あとは変わらない。
- 北の尾根 (高さ14) と南西の山 (13) の水は谷を下って湖に入った (71マスと56マス)。東の端に近い3か所 (15・12・9) の水は東の崖から落ち、外の平地にひし形の水たまりを3つ作った (合わせて167マス)。
- 湖の水はそのまま。壊れたブロックはない。水の下の草が時間とともに土に変わる (5秒で7、5分で44)。

## やったこと
- `index.html`: `peakWater(vol, N, HY, max = 3)` を `mcBlocks()` の前に追加。峰の候補 (半径4マスの中で地面がいちばん高く、上が空いているマス) を高い順に試し、ゲームと同じ流れ方で水を流してみて、風景の外に出ない、かつ3マス以上下る峰だけを選ぶ。選んだ峰どうしは8マス以上離す。最大3か所。
  - 流れ方は 26.3 の `FlowingFluid` に合わせた: 下が空いていれば真下に落ちる (落ちた先は強さが戻る)。地面の上では、4マス以内のいちばん近い「落ちる所」の方向にだけ広がり、なければ4方向に広がる。1マスごとに1段弱くなり、7段で止まる。湖の水に入ったら止まる。風景の外は「落ちる所」として扱い、そこに流れたら失格。
- `mcBlocks()`: 「山の上から水を流す」がオンで冬でなければ、選んだマスに `water` を置く。戻り値に `springs` (置いた数) を足した。
- 画面: 書き出しの欄に「山の上から水を流す（マインクラフト用）」のチェック (`#peakWater`、風景のときだけ見える) と説明 (`#peakWaterNote`)。保存のお知らせに、置いた数 (または置かなかった理由) を足した。
- `docs/public/index.md` / `.html` (てびき) に1行、`docs/public/minecraft.md` / `.html` に「山の上から水を流す (試験中)」の節を足し、`python3 tools/build_guide.py` で作り直した。

## 追記: ゲームの画面での確認と、くぼみを池にする直し (2026-11-20)
- ユーザーがゲームの画面で、上の zip (山と湖・夏・番号12、水3か所) を置いた。風景の外にはこぼれなかった。3か所のうち1か所は湖に届かなかった (スクリーンショットはマインクラフトの `screenshots` の 2026-11-20_10.14.00.png)。
- 計算でも同じ: 北の尾根 (vol 座標 31,15,2) の水は33マス流れ、高さ11のくぼみで止まる。ほかの2か所は湖の水面 (高さ5) まで届く。
- 選択肢として「湖に届く峰だけにする」(1) と「このまま」(2) を出し、ユーザーは「2でもっと湖のようにたまるとよい」と答えた。
- `index.html` の `peakWater()`: 地面の高さに「priority flood」をかけ、各列で水がこぼれずに立てる高さ (`brim`) を求める (風景の端と湖を出口にする)。流れた水が `brim > 地面` の列 (くぼみ) に入ったら、同じ `brim` でつながる列を、地面の上から `brim` の高さまで水源で満たす (空いているマスだけ。幹や葉はそのまま)。戻り値を `{ springs, ponds }` に変え、`mcBlocks()` で両方に `water` を置く。
- 番号12では、北の水の先が8マス (深さ1) の池になる。秋・山の高さ40・64マスの風景では2マスの池ができた。島7と丘30では池はできない (流れはどれもくぼみに止まらない)。

## 追記: 消したあとに水がゆっくり消える (2026-11-21)
- ユーザーが池つきの zip をゲームの画面で置いた (スクリーンショットは `screenshots` の 2026-11-21_04.40.07〜04.43.06.png)。山の水が滝になって湖まで流れるのを確認。池は写っていない (**未確認**)。
- 「できあがりました」の [消す] (`voxel:break_here`) で消すと、空中に水の柱が残って地面に落ち、ゆっくり消えた。
- 原因: `clear/c*.mcfunction` は、置いたブロックのマスだけを `fill … minecraft:air` で消す。流れた水は、もとは空気のマスにあるので消す対象に入らず、水源がなくなってから数秒かけて引く (ゲームのしくみ)。前のサーバーでの確認は、消してから600ティック後に数えたので見えなかった。サーバーで `voxel:break_here` を同じ場所で打つと、600ティック後に残るブロックは0。
- 直す案 (消す前に範囲全体の水を空気にする) を出したが、ユーザーは「なおさなくてもいい」と答えた。説明ページの「流れた水も消えます」を「少しあとに消えます」に直した。
- 最初、消え残りを「前の風景が残っていた」と推測して伝えたが、まちがいだった。

## 追記: 一気に消すときは水もすぐ消す (2026-11-21)
- ユーザーが「breakだったらすぐ水を消せたほうがいいかな」と言い直した。
- `index.html` の保存処理: モデルに `water` があるとき、`clear/c0.mcfunction` の先頭に、モデルの箱全体 (`~2 ~0 ~0` から `~w+1 ~h-1 ~d-1`) を `fill … minecraft:air replace minecraft:water` で空にする行を足した (1回の `/fill` が 32,768 マス以下になるよう、段ごとに分ける)。`voxel:break` と `voxel:break_here` の両方がこれを通る。`voxel:break_slow` は変えていない。
- 確認済み (サーバー26.3): 山と湖12を `voxel:break` と `voxel:break_here` で、高い秋の64マスを `voxel:break` で消した。`tick freeze` で時間を止めたまま消して保存すると、水も他のブロックも0。30秒後も0。
- 説明ページは「流れた水も一緒にすぐ消えます」に戻した。
- ゲームでも確認 (2026-11-21): ユーザーがログの [消す] で消し、流れた水もすぐ消えたと報告。北の尾根の下の池はまだ見ていない。
- ゲームのキャプチャ (2026-11-21): 北の峰の流れは雪の下から岩を下り、ふもとで止まって草地にはこぼれていない。池の水面は木の葉に隠れて形まではわからない。
